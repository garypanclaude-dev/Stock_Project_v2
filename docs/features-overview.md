## 為什麼有六個系統？

本平台針對「投資決策」的不同階段，各自有獨立的評估系統：

| 階段 | 我想知道... | 用哪個 |
|------|-----------|--------|
| 1. 全市場掃描 | 全台 1,970 支裡哪幾支最值得關注？ | **潛力股篩選** |
| 2. ML 預測 | 哪些股票未來 5 日最可能打敗大盤？ | **ML 推薦清單** |
| 3. 個股初評 | 這支股票值不值得買？ | **綜合投資評分** |
| 4. 同業檢視 | 跟同產業比是強是弱？ | **同業比較** |
| 5. 風險評估 | 買了之後最壞會虧多少、何時該停損？ | **風險指標** |
| 6. 自選股管理 | 我的 watchlist 裡誰最強？ | **自選股比較** |

每個系統的設計目的不同，**評分方式、資料來源、指標也都不同**。本文件提供總覽，深入細節請查各自的 spec 文件。

## Feature 1：綜合投資評分 (Composite Investment Score)

### 解決的問題
給單一股票一個 **0-100 分**的綜合評價，回答「值不值得買？」

### 資料來源
- **yfinance**：完整 OHLCV K 線、基本面 info、季度財報
- **Gemini AI**：文字研判（綜合分析摘要）

### 使用的指標與計算方式

**技術面 55%**（6 個子指標，v2.0 升級）

| 子指標 | 權重 | 公式（精簡版） | 結論方式 |
|--------|------|------------|---------|
| RSI(14) | 15% | `RSI = 100 - 100/(1+RS)`，RS = 14 日平均漲幅 / 平均跌幅 | 查表：< 30 超賣加分，> 70 超買扣分 |
| MACD(12,26,9) | 15% | `MACD = EMA12 - EMA26`，Signal = EMA9(MACD)，Histogram = MACD - Signal | 4 種狀態：多頭擴大 80、多頭縮小 65、空頭縮小 45、空頭擴大 20 |
| 均線排列 | 20% | MA5/10/20/60 + 收盤價的 4 態分類 | 多頭排列 90 / 空頭排列 15 / 糾結 50 / 中性 50 |
| 布林通道位置 | 15% | `position = (價 - 下軌) / (上軌 - 下軌)` | 查表：< 10% → 70 分，> 90% → 30 分 |
| **KD(9,3,3)** | 20% | `RSV = (C-L9)/(H9-L9)×100`，K/D 為 1/3 平滑 | K 值查表 + 黃金/死亡交叉 ±10 |
| **OBV** | 15% | 累積量能（漲 +volume / 跌 -volume） | 5 日 OBV 斜率 vs 5 日股價斜率比對 |

**v2.1 修正項：K 線型態（B8）**

技術面 6 子指標加總後，依近 5 日內出現的反轉型態做最終修正：
- 看多型態（錘子 / 看多吞噬 / 晨星）每次 **+3 分**
- 看空型態（流星 / 看空吞噬 / 夜星）每次 **-3 分**
- 十字線：0（純資訊性）
- 總修正上限 **±10 分**

**基本面 45%**（5 個子指標，v2.2 升級）

| 子指標 | 權重 | 公式（精簡版） | 結論方式 |
|--------|------|------------|---------|
| P/E (TTM) | 20% | yfinance `trailingPE` + 5 年歷史分位 | 絕對閾值 + 歷史分位 ±15 修正 |
| ROE | 20% | yfinance `returnOnEquity` | 查表：> 25% → 90 分，< 0 → 10 分 |
| 營收趨勢 | 25% | 連續 QoQ + 年度 YoY 雙重判定 | QoQ 基礎分 + YoY ±10 修正 |
| Profit Margin | 15% | yfinance `profitMargins` | 查表：> 30% → 90 分，< 0 → 10 分 |
| 殖利率 | 20% | yfinance `dividendYield` + 連續配息年數 | 殖利率基礎分 + 連續年數 +20 上限 |

> **v3.0 變更**：情緒面（新聞分析）維度已移除，權重重分配為技術面 55% / 基本面 45%。

### 結論如何得出

```
綜合評分 = 技術面 × 0.55 + 基本面 × 0.45
```

| 分數 | 等級 |
|------|------|
| 81-100 | 強勢 |
| 61-80 | 偏多 |
| 41-60 | 中性 |
| 21-40 | 偏空 |
| 0-20 | 弱勢 |

加上 Gemini 生成的 100 字內中文研判（如 AI 失敗則只顯示分數，研判顯示「暫時不可用」）。

→ 完整閾值與權重查 [`docs/composite-score.md`](./composite-score.md)

## Feature 2：風險指標 (Risk Metrics)

### 解決的問題
給單一股票的「風險面」做量化，回答「買了最壞會虧多少、何時該停損？」

### 資料來源
- 該股票的 kline（OHLCV）+ indicators（重用布林通道）
- **不需額外 API 呼叫**

### 使用的指標與計算方式

| 指標 | 公式（精簡版） | 結論方式 |
|------|------------|---------|
| 歷史波動率 HV | `HV = std(對數報酬) × √252 × 100%`，採 20 日和 60 日兩個視窗 | 4 級：< 20% 低 / 20-40% 中 / 40-60% 高 / > 60% 極高 |
| 最大回撤 MDD | `peak_i = max(P_0..P_i)`，`drawdown_i = (P_i - peak_i) / peak_i`，取整段最小值 | 3 級：> -15% 綠 / -15% ~ -30% 黃 / < -30% 紅警示 |
| ATR(14) | `True Range = max(H-L, \|H-prev_C\|, \|L-prev_C\|)`，Wilder 14 日平滑 | 提供停損停利幅度的基礎 |

### 停損停利四法（並列對照）

| 方法 | 停損公式 | 停利公式 | R:R |
|------|---------|---------|-----|
| ATR 標準 | `current - 2.5 × ATR` | `current + 5.0 × ATR` | 1:2.0 |
| 固定百分比 | `current × 0.92`（-8%） | `current × 1.15`（+15%） | 1:1.87 |
| 布林通道 | 布林下軌（最新值） | 布林上軌（最新值） | 動態 |
| 波段支撐壓力 | 近 60 日最低點 | 近 60 日最高點 | 動態 |

> ATR 還有 conservative（2.0× / 3.0×）和 aggressive（3.0× / 6.0×）兩種額外配置，共三種風險偏好。

### 結論如何得出

**不計算成單一分數**，並列呈現讓使用者交叉驗證：

- **HV** → 等級 + 顏色（決定操作策略激進度）
- **MDD** → % 數值 + 是否回復 + 距高點當前回撤
- **四法對照表** → 四個停損價聚集 = 強支撐，分散 = 結構不清楚

### 警示燈號（v1.1 新增）

風險卡頂部會出現自動偵測的警示 banner（不影響數字）：

| 警示 | 觸發條件 |
|------|---------|
| 🟠 KD 高檔死亡交叉 | K > 70 且 K 由上穿越 D |
| 🟠 OBV 看空背離 | 近 10 日股價漲但 OBV 跌 |
| 🔴 均線空頭排列 | MA5 < MA10 < MA20 < MA60 且 收盤 < MA5 |
| 🟠 近期看空反轉型態（v1.2） | 近 5 日出現流星 / 夜星 / 看空吞噬 |

**設計哲學**：風險指標**不納入綜合評分**。避免「機會分」與「風險分」混為一談造成雙重懲罰（好股票如果波動高，會在兩邊都扣分）。

→ 完整公式與設定檔查 [`docs/risk-metrics.md`](./risk-metrics.md)

## Feature 3：同業比較 (Peer Comparison)

### 解決的問題
看完個股後想知道「跟同產業比是強是弱？」

### 資料來源
- **yfinance**：每支 peer 的 `info`（PE / ROE / Margin / yield / Beta / 市值）+ 區間 kline（算報酬）
- **同業匹配**：硬編碼表（美股）/ SQLite industry 欄位（台股）

### 同業匹配邏輯（三層 fallback）

```
Step 1: PEER_MAP 硬編碼（僅美股，如 AAPL → [MSFT, GOOGL, META]）
Step 2: SQLite companies.industry（台股，按最新成交量取前 3，排除自己）
Step 3: 無 peers → 只顯示該股 + 大盤指數
```

### 使用的指標與計算方式

對 target + peers + 大盤指數，**每支股票**取得以下欄位：

| 指標 | 計算方式 | 用途 |
|------|---------|------|
| **基本面分數** | 重用 `scoring._score_fundamental`（PE 20% + ROE 20% + 營收 25% + Margin 15% + Yield 20%） | 快速判斷誰基本面最好 |
| P/E (TTM) | yfinance `trailingPE` | 估值比較 |
| ROE | yfinance `returnOnEquity` | 獲利效率 |
| Profit Margin | yfinance `profitMargins` | 成本控制 |
| 市值 | yfinance `marketCap` | 規模量級 |
| 區間報酬率 | `(closes[-1] / closes[0] - 1) × 100` | 股價表現 |
| 殖利率 | yfinance `dividendYield` | 配息能力 |
| Beta | yfinance `beta` | 波動風險 |

### 相對走勢圖
- 每支股票的 closes 標準化（首日 = 100）
- 大盤指數選擇：`.TW` → 0050.TW，`.SS/.SZ` → 000300.SS，其他 → SPY

### 結論如何得出

**不算單一綜合結論**，呈現為兩個視覺元件：

1. **比較表格**：橫向對照各指標，誰高誰低一目了然
2. **相對走勢圖**：標準化後的折線圖，誰漲得快、誰輸給大盤

**注意**：這裡的「分數」**只反映基本面**（無技術面，因為對 peers 不抓 RSI/MACD 等技術指標），所以**同業比較的分數和綜合投資評分的分數會不一樣**。

→ 完整邏輯查 [`docs/peer-comparison.md`](./peer-comparison.md)

### 解決的問題
管理多支自選股時想知道「我的持股裡誰最強？」

### 與同業比較的差異
**邏輯幾乎完全相同**，只差在股票來源：

| | 同業比較 | 自選股比較 |

## Feature 5：潛力股篩選 (Stock Screener)

### 解決的問題
全市場掃描「全台 1,970 支股票中哪幾支最值得關注？」

### 資料來源
- **SQLite** (`data/tw_market.db`)：60 個交易日的 close / volume / PE / PB / yield 歷史
- 來源 API：TWSE MI_INDEX + BWIBBU_d + TPEX otc_quotes + peratio_analysis

**為什麼用 SQLite 而非 yfinance？**
- 1,970 支股票逐支 yfinance 抓需數小時，TWSE/TPEX 批次 API 一天只需 4 次呼叫
- 需要多日歷史才能算 5d/20d 動能、MA 多頭排列、量能比

### 前置篩選（排除不適合的股票）
- 日均量 < 500 張 → 流動性不足
- 代號非 4 碼純數字 → 特別股、ETF、權證
- 收盤價為 0 → 無成交紀錄

### 使用的指標與計算方式

**14 因子百分位排名模型（v7.1：技術面 50% / 籌碼面 35% / 基本面 15%）**

> 完整因子定義與權重請查 [`docs/peer-comparison.md`](./peer-comparison.md)

核心策略：捕捉波動壓縮後帶量突破的起漲股。技術面強調 BB squeeze + 量突破 + 箱型突破組合，籌碼面以投信為主力、外資為輔助，基本面看營收雙增（YoY + MoM）。

**百分位排名說明**：每個因子轉成 0-100 分。例：投信淨買超排名 88 = 該股投信買超金額超過 88% 的股票。

### 結論如何得出

```
分數 = Σ(因子百分位 × 權重)
排名 = 按分數降序取 Top 20
```

呈現為排行榜表格（排名、代號、名稱、分數、收盤、漲跌幅、PE、殖利率、量）。點擊任一行可直接切換到該股的完整分析。

**和綜合評分的關鍵差異**：

| | 綜合評分 | 潛力股篩選 |
|---|---|---|
| 評分方式 | **絕對閾值**：PE < 15 → 75 分（不管別人） | **百分位排名**：PE 排名前 20% → 80 分（跟全市場比） |
| 適用場景 | 看單一股票時 | 從 1,970 支中挑時 |

→ 完整因子定義查 [`docs/peer-comparison.md`](./peer-comparison.md)

## Feature 6：ML 推薦清單 (ML Recommendation)

### 解決的問題
用機器學習模型預測「哪些股票最可能在未來 10 個交易日內出現爆發性起漲（intraday 漲幅 +10% 以上）？」，並依機率分級推薦。

### 為什麼選擇 Triple-Barrier 分類而非報酬率迴歸
舊版（v3.0）用迴歸預測 5 日超額報酬率，會把「超賣崩跌中的股票」誤判為高分（因為超賣後常伴隨短期反彈）。實務上經理人關心的不是「短期反彈」而是「波段起漲」，這兩種型態的籌碼結構完全不同。Triple-Barrier 透過「先觸頂 vs 先觸底」的路徑判定，直接把目標定義為「起漲」，模型自然會學會避開崩跌中的反彈陷阱。

### 與潛力股篩選的差異

| | 潛力股篩選 | ML 推薦清單 |
|---|---|---|
| 方法 | 規則式：14 因子百分位加權 | 機器學習：LightGBM 二元分類 (Triple-Barrier) |
| 權重來源 | 人工設定（經理人調校） | 模型從歷史資料自動學習 |
| 輸出 | 0-100 加權分數 | 起漲機率 (%) + 推薦等級 |
| 特徵處理 | 百分位排名（相對值） | 原始值（絕對值） |
| 目標定義 | 無明確 label | Triple-Barrier：10 日內 intraday +10% 觸頂 → 1 |

### 資料來源
- **SQLite** (`data/tw_market.db`)：與潛力股篩選共用同一份資料（每日價量、法人買賣超、月營收、大戶持股）
- **模型檔**：`data/ml_model.txt`（LightGBM 模型）、`data/ml_model_meta.json`（訓練元資料）

### Label 定義：Triple-Barrier Method (de Prado)

```
買入日 = 訊號日隔天（T+1），以開盤價買入
往前掃描最多 10 個交易日，每日比對 intraday 高低點：
  若 day.high  >= buy_open × 1.10  → Y = 1（先觸頂 = 起漲成功）
  若 day.low   <= buy_open × 0.95  → Y = 0（先觸底 = 停損出場）
  10 天到期皆未觸及                → Y = 0（震盪盤）
```

**關鍵參數**：
- `UPPER_BARRIER_PCT = 10.0`（上軌）
- `LOWER_BARRIER_PCT = -5.0`（下軌）
- `MAX_HOLDING_DAYS = 10`

**為何用 intraday 而非收盤**：模型要捕捉「最高漲到哪、最低跌到哪」的路徑資訊，用收盤會錯估觸頂時機。

**為何同日上下軌都觸及視為觸下**：保守處理，避免訓練時高估正樣本率。

### 推論分級

| 等級 | 預測起漲機率 | 前端顯示 |
|------|------------|---------|
| high（強力推薦） | ≥ 70% | ★★★ |
| medium（中等推薦） | ≥ 50% | ★★ |
| low（一般） | < 50% | ★ |

### 前置過濾（不算特徵，但決定哪些股票進入模型）

| 過濾條件 | 門檻 | 原因 |
|---------|------|------|
| MA200 | 收盤 < 200 日均線 → 排除 | 只看中長期多頭趨勢股 |
| 最低成交量 | 日均量 < 500 張 → 排除 | 流動性不足 |
| 極端報酬 | \|報酬\| > 30% → 排除（僅訓練） | 排除除權息 / 異常交易的雜訊 |
| 最短歷史 | 歷史資料 < 60 日 → 排除 | 技術指標計算不穩定 |

### 訓練特徵（21 維）

特徵使用**原始值**輸入模型（非百分位），讓 LightGBM 自行學習最佳分割點。

#### 技術面（14 維）

| # | 特徵名稱 | 說明 | 計算方式 |
|---|---------|------|---------|
| 1 | `bb_squeeze` | 布林帶寬擠壓度百分位 | 計算 `bandwidth = (上軌 - 下軌) / 中軌`，再計算「過去 60 天中 bandwidth ≥ 今天的比例」（%）。**值越高 = 帶寬越窄 = 真正的擠壓蓄勢**；值越低 = 帶寬寬 = 波動放大中（非擠壓）。v3.3 變更：lookback 從 120→60 天以對齊 10 日預測視野，並翻轉語義（100 = 最擠，與直覺一致）|
| 2 | `volume_breakout` | 量能突破倍數 | 當日成交量 / 20 日均量。衡量放量程度 |
| 3 | `box_breakout` | 箱型突破強度 | `100 / max(箱型振幅%, 1)`。振幅越小（越盤整）值越高 = 突破能量越集中 |
| 4 | `squeeze_volume` | 壓縮量能複合因子 | BB squeeze × 量比乘積。同時壓縮且放量才會高 |
| 5 | `avwap_dev` | AVWAP 偏離度 | `(現價 - Anchored VWAP) / AVWAP × 100%`。正值 = 站上均量成本線 |
| 6 | `near_breakout` | 20 日高點突破幅度 | `(現價 - 20d high) / 20d high × 100%`。正值 = 創新高 |
| 7 | `price_position` | 價格位階 | 現價在近期價格區間中的相對位置（%），衡量當前處於區間高位或低位 |
| 8 | `tangled_ma` | 均線糾結度 | MA5/10/20/60 的 max-min spread。越小 = 均線越收斂、即將選擇方向 |
| 9 | `liquidity_sweep` | 流動性掃蕩 | 下影線深入近期低點的程度。衡量洗盤後回升力道 |
| 10 | `obv_divergence` | OBV 背離度 | OBV 趨勢與價格趨勢的背離程度 |
| 11 | `volume_contraction` | 量縮收斂 | 近期成交量相對歷史的萎縮程度 |
| 12 | `k_value` | KD 的 K 值 | Stochastic K（9,3,3），範圍 0-100 |
| 13 | `d_value` | KD 的 D 值 | Stochastic D（9,3,3），範圍 0-100 |
| 14 | `k_minus_d` | K - D 差值 | 正值 = 黃金交叉狀態，負值 = 死亡交叉狀態 |

#### 籌碼面（5 維）

法人淨買超已**去量綱化**：除以「5 日均量 × 5」轉成佔成交量比例（%），避免大小型股的張數尺度差異干擾模型。保留正負號以維持方向性（正 = 買超、負 = 賣超）。

| # | 特徵名稱 | 說明 | 計算方式 |
|---|---------|------|---------|
| 15 | `trust_net_5d_norm` | 投信 5 日淨買超佔比 | `投信 5 日累計淨買超 / (5日均量 × 5) × 100%`。台股主動型基金的核心風向標，正值 = 投信買超主導，負值 = 投信賣超 |
| 16 | `foreign_net_5d_norm` | 外資 5 日淨買超佔比 | `外資 5 日累計淨買超 / (5日均量 × 5) × 100%`。正值 = 外資買超，負值 = 外資賣超 |
| 17 | `inst_volume_ratio` | 法人關注度 | `(\|外資5日淨買超\| + \|投信5日淨買超\|) / (5日均量 × 5) × 100%`。**不分方向的法人參與強度**，取絕對值是為了捕捉「不論進出，只要法人在動作就代表這支股票有關注」。與上面兩個方向性特徵互補 |
| 18 | `trust_streak` | 投信連買天數 | 正值 = 連續買超 N 天，負值 = 連續賣超 N 天 |
| 19 | `foreign_streak` | 外資連買天數 | 正值 = 連續買超 N 天，負值 = 連續賣超 N 天 |

#### 基本面（2 維）

| # | 特徵名稱 | 說明 | 計算方式 |
|---|---------|------|---------|
| 20 | `revenue_yoy` | 營收年增率 | 最新月營收 vs 去年同月（%） |
| 21 | `revenue_mom` | 營收月增率 | 最新月營收 vs 上月（%） |

### 訓練方法：Walk-Forward Expanding + Purge Gap

金融時序資料不能用傳統的隨機 K-Fold 交叉驗證（會造成未來資訊洩漏）。本模型採用 **Walk-Forward Expanding Window** 搭配 **Purge Gap**，確保 OOS（Out-of-Sample）指標真實可靠。

#### 為什麼不能隨機切 Train / Test？

```
[隨機切割的問題]

時間軸:  ──── D1 ── D2 ── D3 ── D4 ── D5 ── D6 ────
隨機切:  train  test  train  train  test  train
                 ↑                    ↑
               D2 的 label 用了 D3~D12 的價格（未來）
               但 D3 在 train 裡 → 模型「見過」未來價格 → AUC 虛高
```

#### Walk-Forward Expanding 流程

```
時間軸:  ━━ D1 ━━ D2 ━━ ... ━━ D60 ┃ purge ┃ D66 ━━ ... ━━ D85 ┃ purge ┃ D91 ...
         ├──── Train (expanding) ───┤ 5 days ├──── Test Fold 1 ──┤ 5 days ├── ...

Fold 1:  [D1 ─────────────── D60]  gap  [D66 ── D85]
Fold 2:  [D1 ──────────────────────────── D85]  gap  [D91 ── D110]
Fold 3:  [D1 ─────────────────────────────────────── D110]  gap  [D116 ── D135]
  ...        ← 訓練窗口持續擴大 →              ← 每個 fold 固定 20 天 →
```

每個 fold 步驟：
1. **Train**：用 D1 到 train_cutoff 的所有樣本訓練 LightGBM
2. **Purge**：跳過接下來 5 個交易日的樣本（不用於訓練也不用於測試）
3. **Test**：在接下來 20 個交易日的樣本上做預測，收集 OOS 預測值
4. **Expand**：將 test fold 併入下一輪的訓練窗口，重複

最終將所有 fold 的 OOS 預測合併，計算整體 **OOS AUC** 和 **Precision@Top10**。

#### Purge Gap 的必要性

```
signal_date = T 的樣本：
  ├── 特徵：用 T 及之前的歷史價量計算
  └── Label：用 T+1 開盤 + T+1~T+11 的 intraday high/low 計算（Triple-Barrier）

若 train 最後一天 = T_cutoff，其 label 依賴 T_cutoff+1 ~ T_cutoff+11 的價格
若 test 第一天 = T_cutoff+1，其特徵包含 T_cutoff+1 的價格
→ 價格重疊 = 資訊洩漏
```

Purge Gap = `MAX_HOLDING_DAYS`（10 天），確保訓練 label 的前瞻窗口（Triple-Barrier 掃描期）與測試特徵的觀測窗口**完全不重疊**。

#### 最終模型

Walk-Forward 只用於評估模型品質（產出 OOS AUC 和 Precision@Top10）。最終用於線上預測的模型是以**全量資料**重新訓練的版本，最大化可用資訊。

#### 設定參數

| 參數 | 值 | 說明 |
|------|---|------|
| `PURGE_GAP_DAYS` | 10 | 訓練/測試間隔天數（= MAX_HOLDING_DAYS） |
| `WF_FOLD_DAYS` | 10 | 每個測試 fold 涵蓋的交易日數 |
| `WF_MIN_TRAIN_SAMPLES` | 100 | 每個 fold 最少訓練樣本數 |
| `MIN_TRAIN_DAYS` | 60 | 第一個 fold 開始前的最少訓練交易日 |

#### 評估指標

| 指標 | 意義 | 用途 |
|------|------|------|
| **OOS AUC** | 所有 fold 合併的 ROC AUC | **主要排序能力指標**，>0.55 有訊號，>0.65 算不錯 |
| **Precision@Top10** | 預測機率前 10 名中，實際觸頂 (Y=1) 的比例 (%) | **實戰指標**，直接衡量選股效果 |
| IS AUC | 全量訓練後的 in-sample AUC | 參考用，用來偵測 overfitting（IS >> OOS 表示過擬合） |
| Per-fold AUC / P@10 | 每個 fold 獨立的指標 | 觀察模型在不同時期的穩定性 |

### 結論如何得出

```
1. 資料建構：從歷史交易日建立 (特徵, Triple-Barrier label, 日期) 三元組
2. Walk-Forward 評估：Expanding Window + Purge Gap (10d)，收集 OOS 預測 → AUC + Precision@Top10
3. 最終訓練：以全量資料訓練 production model
4. 預測：對最新交易日所有通過前置過濾的股票，輸出起漲機率 (%)
5. 分級：依機率分為 high（≥70%）/ medium（≥50%）/ low（<50%）
6. 排序：按起漲機率降序取 Top 30 呈現
```

**與篩選器的互補關係**：
- **潛力股篩選**是規則式系統，權重由人工設定，透明可解釋
- **ML 推薦清單**是資料驅動，權重由模型自動學習，可能發現人工未注意到的因子組合
- 兩者共用相同的底層資料與因子計算，但處理方式不同（百分位 vs 原始值）
- 建議交叉比對：同時出現在兩個清單的股票可信度更高

→ 程式碼查 [`stock_fetcher/ml_config.py`](../stock_fetcher/ml_config.py) 與 [`stock_fetcher/ml_model.py`](../stock_fetcher/ml_model.py)

## 常見問題

### Q1：為什麼不把這六個系統整合成一個「終極評分」？

**因為每個系統的設計目的不同，混在一起會失真**：

- 綜合評分用絕對閾值（「PE 30 是高還是低？」），但全市場篩選必須用百分位（「PE 30 在 1,970 支中算高還是低？」）。同一個 PE 值在兩個系統的合理分數不同
- ML 推薦清單的起漲機率和其他系統的分數量綱不同，無法直接加總
- 風險指標和機會評估混在一起會雙重懲罰：好公司 + 高波動 = 兩邊都扣分
- 同業比較需要橫向對比，沒有單一絕對標準
- 自選股比較依賴使用者的選擇，本質上不是「全市場評分」

每個系統獨立呈現，**讓使用者依場景組合判斷**，比一個黑盒子分數更負責。

### Q2：同一支股票，這幾個系統算出來的分數為什麼不同？

| 場景 | 例子 | 原因 |
|------|------|------|
| 綜合評分 75 vs 同業比較 60 | AAPL | 同業比較只算基本面（沒技術面），分數會偏向中性 |
| 綜合評分 80 vs 潛力股篩選沒入榜 | 台積電 2330 | 潛力股篩選看「現在是不是強勢時機」，台積電基本面好但 PE 排名差（被同業比下去） |
| 風險指標 HV 高 但綜合評分高 | NVDA | 高波動本來就伴隨高機會，分開呈現才不會誤判 |

**結論：分數不是用來比大小的，是用來對應不同決策場景的。**

### Q3：哪個系統的判斷最可信？

**沒有「最可信」，每個系統都只反映設計者選定的維度**。建議組合使用：

1. 用 **潛力股篩選** 或 **ML 推薦清單** 從全市場挑出值得關注的標的（兩個清單交集可信度更高）
2. 切到該股的 **綜合投資評分** 做深入分析
3. 對照 **同業比較** 確認是否真的領先同業
4. 最後看 **風險指標** 設定停損停利

### Q4：什麼時候用哪個指標？快速對照

| 我的需求 | 用哪個 |
|---------|--------|
| 想找一支新的股票投資（規則式） | 潛力股篩選 |
| 想找一支新的股票投資（ML 預測） | ML 推薦清單 |
| 朋友推薦了一支，想評估 | 綜合投資評分 |
| 已經看好一支，想確認不是被同業甩開 | 同業比較 |
| 已經買進，想設停損停利 | 風險指標 |
| 想清理自選股，留下最強的幾支 | 自選股比較 |
